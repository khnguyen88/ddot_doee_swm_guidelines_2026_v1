# SWM Summary Calculator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a standalone single-file HTML webpage that reads the filled `SW_Required_Provided_DOEE_EISA438.xlsx` template and renders letter-size printable calculation summaries (cover, Site DA, Site SWRv, SDA/CDA summary, one page per BMP, MEP, EISA 438, filtered Detention, Compliance roll-up).

**Architecture:** ES-module source in `summary_calculator/src/*.mjs` for testability under Node 20+, plus a `build.js` concatenator that inlines all modules, CSS, and SheetJS into a single-file dist HTML that opens offline from `file://`. Mirrors the proven pattern of `C:\_AAA\WS_HH\SD-HH-calculator-vc-v1\drainage-calculator`.

**Tech Stack:** Vanilla ES modules (no bundler), SheetJS (vendored), Node 20+ test runner (`node --test`), Playwright (dev-time only), Python 3 (`workbook.calculations` is the reference ground truth).

**Spec:** `docs/superpowers/specs/2026-10-28-swm-summary-calculator-design.md`

**Scope note:** This plan covers **Webpage A** only. Webpage B (template → DOEE calculator populator) is a separate future plan.

## Dev loop

- `node summary_calculator/build.js` — rebuild dist
- `node --test summary_calculator/tests/*.test.mjs` — unit + parity tests (fast)
- `python scripts/dump_reference.py` — regenerate reference JSON (run when calculations.py changes)
- `npx playwright test summary_calculator/tests/browser-smoke.mjs` — dev-time smoke
- Dev-time server: `python -m http.server 8000` from repo root, then open `http://localhost:8000/summary_calculator/summary-calculator-dev.html` (ESM over `file://` is blocked; dist opens from `file://` fine)

## Conventions

- **TDD.** Each task writes the failing test first, confirms failure, implements minimally, confirms pass, commits.
- **Commits** follow project convention from `.claude/CLAUDE.md`: plain language, no AI references, focus on the "why" of the change.
- **Scope per task:** one commit at the end unless a task explicitly says otherwise.
- **Units:** CF for volumes, inches for depths, SF for areas (same as `calculations.py`).
- **Tolerance:** parity test uses 0.5 CF for volumes, 0.001 in for depths.
